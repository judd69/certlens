Certs expire.
Services shouldn't.

CertLens X-rays X.509 certificates — files, keystores, live hosts — and tells you, in one verdict, whether anything is expired, weak, or about to expire.

View the sample report  Repo: judd69 / certlens

Every input

PEM files and multi-cert bundles, DER files, JKS / PKCS12 keystores, and live host:port checks over a real TLS handshake — with the served chain captured, not just the leaf.

Real analysis

Validity windows, days remaining, SANs, signature algorithm, key type and size, self-signed detection, and hostname matching that is wildcard-aware and case-insensitive.

Weak flags

MD5 / SHA1 signatures, RSA under 2048 bits, EC under 224, any DSA, expired, not-yet-valid, and hostname mismatch — each named, not hidden behind a score.

One verdict

EXPIRED beats WEAK beats EXPIRING beats HEALTHY. Gate CI with --fail-on and get exit code 1 before a bad cert ships.

How it works

  1. Point it at a cert: certlens cert.pem
  2. Or a live service: certlens --host example.com
  3. Read the verdict, or gate a pipeline: certlens --fail-on expired *.pem
  4. Ship the evidence: certlens --format html --output report.html *.pem

What it flags

  • MD5 / SHA1 signatures
  • RSA < 2048 bits
  • EC < 224 bits
  • Any DSA key
  • Expired / not yet valid
  • Hostname mismatch
  • Self-signed (reported, not flagged)
